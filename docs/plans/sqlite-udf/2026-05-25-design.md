# SQLite phase 2: UDF/UDAF/window function bindings — design

**Date:** 2026-05-25
**Depends on:** [PR #15 (SQLite buildout)](https://github.com/Goykhman/numbox/pull/15) — must merge first
**Branch:** `feat/sqlite-udf` (off `origin/main` post-PR-#15)
**Target:** fork PR (`nelson2005/numbox`) → upstream PR (`Goykhman/numbox`)

## Summary

Add 34 new bindings and 4 constants to enable user-defined scalar, aggregate, and window functions in SQLite from `@njit` code. Covers the full `sqlite3_value_*` accessor surface (read UDF arguments), `sqlite3_result_*` setter surface (write UDF return values), and the registration + context functions (`sqlite3_create_function_v2`, `sqlite3_create_window_function`, `sqlite3_aggregate_context`). Aggregate and window UDFs use the structref-backed state pattern from numbduck — `export_meminfo` / `borrow_structref` / `release_meminfo` from `numbox/utils/meminfo.py` bridge NRT-managed state to SQLite's raw aggregate context pointer.

No new architectural primitives. Every wrapper is `@proxy(signatures.get("name"), jit_options={"cache": True})` around `_call_lib_func("name", (args,))`, matching phase 1's convention.

## 3. Callback signatures

All UDF callbacks map to `@cfunc` signatures using `intp` for opaque pointers:

### 3.1 Scalar

```
xFunc:    void(intp, int32, intp)    # ctx, argc, argv_pp
xDestroy: void(intp)                 # pApp
```

### 3.2 Aggregate

```
xStep:    void(intp, int32, intp)    # ctx, argc, argv_pp
xFinal:   void(intp)                 # ctx
xDestroy: void(intp)                 # pApp
```

### 3.3 Window

```
xStep:    void(intp, int32, intp)    # ctx, argc, argv_pp
xFinal:   void(intp)                 # ctx (teardown — release_meminfo here)
xValue:   void(intp)                 # ctx (read current value — no release)
xInverse: void(intp, int32, intp)    # ctx, argc, argv_pp (undo an xStep)
xDestroy: void(intp)                 # pApp
```

### 3.4 Accessing argv inside callbacks

`argv_pp` is a `sqlite3_value**`. To read argument `i`, dereference `argv_pp + i * sizeof(intp)` to get a `sqlite3_value*`, then pass that to `sqlite3_value_int` / `_text` / etc. In `@njit`:

```python
args = carray(_cast_int_to_void_p(argv_pp), (argc,), dtype=numpy.intp)
val = sqlite3_value_int(args[0])
```

Same pattern numbduck uses for DuckDB's state pointer arrays.

### 3.5 Callback wiring pattern

Follows phase 1's `_sqlite_hooks.py` convention — `@njit` implementation + thin `@cfunc` wrapper:

```python
@njit
def _my_func_impl(ctx, argc, argv_pp):
    args = carray(_cast_int_to_void_p(argv_pp), (argc,), dtype=numpy.intp)
    val = sqlite3_value_int(args[0])
    sqlite3_result_int(ctx, val * 2)

@cfunc(nb_types.void(nb_types.intp, nb_types.int32, nb_types.intp))
def _my_func_cb(ctx, argc, argv_pp):
    _my_func_impl(ctx, argc, argv_pp)
```

Registration:

```python
sqlite3_create_function_v2(
    db_p, name_p, 1, SQLITE_UTF8 | SQLITE_DETERMINISTIC,
    0,                    # pApp (NULL)
    _my_func_cb.address,  # xFunc
    0, 0, 0               # xStep, xFinal, xDestroy (NULL — scalar)
)
```

## 4. UDAF structref pattern via `sqlite3_aggregate_context`

### 4.1 Memory ownership

`sqlite3_aggregate_context(ctx, nBytes)` allocates `nBytes` of zeroed memory on first call per aggregate group, returns the same pointer on subsequent calls. **SQLite owns this memory** — it frees it after `xFinal` completes. Numba sees the return value as a raw `intp` and will not attempt to free it via NRT.

The 8 bytes from `sqlite3_aggregate_context` store a single `intp` — the NRT meminfo pointer to a structref. NRT owns the structref; `release_meminfo` in `xFinal` decrefs it and triggers the destructor at refcount 0. Nested allocations (e.g., `typed.List` inside the structref) are freed by NRT's destructor.

### 4.2 Lifecycle

```python
# 1. Define structref + proxy
@structref.register
class SumStateType(nb_types.StructRef):
    def preprocess_fields(self, fields):
        return tuple((n, nb_types.unliteral(t)) for n, t in fields)

class SumState(structref.StructRefProxy):
    def __new__(cls, total):
        return structref.StructRefProxy.__new__(cls, total)

structref.define_proxy(SumState, SumStateType, ["total"])
sum_state_type = SumStateType([("total", nb_types.int64)])

# 2. xStep — accumulate
@njit
def _sum_step_impl(ctx, argc, argv_pp):
    agg_ptr = sqlite3_aggregate_context(ctx, 8)
    args = carray(_cast_int_to_void_p(argv_pp), (argc,), dtype=numpy.intp)
    val = sqlite3_value_int64(args[0])
    slot = carray(_cast_int_to_void_p(agg_ptr), (1,), dtype=numpy.intp)
    if slot[0] == 0:
        # First call — allocate structref, export meminfo
        s = SumState(0)
        slot[0] = export_meminfo(s)
    state = borrow_structref(sum_state_type, slot[0])
    state.total += val

# 3. xFinal — produce result, release
@njit
def _sum_final_impl(ctx):
    agg_ptr = sqlite3_aggregate_context(ctx, 0)  # 0 = don't allocate
    if agg_ptr == 0:
        # xStep never called (empty group)
        sqlite3_result_int64(ctx, 0)
        return
    slot = carray(_cast_int_to_void_p(agg_ptr), (1,), dtype=numpy.intp)
    if slot[0] == 0:
        sqlite3_result_int64(ctx, 0)
        return
    state = borrow_structref(sum_state_type, slot[0])
    sqlite3_result_int64(ctx, state.total)
    release_meminfo(slot[0])
```

### 4.3 Safety properties

1. **SQLite owns the 8-byte slot** — numba sees it as raw `intp`; NRT won't free it
2. **NRT owns the structref** — `export_meminfo` increfs; `release_meminfo` decrefs and triggers destructor at refcount 0
3. **`xFinal` with `nBytes=0`** — returns NULL if `xStep` never ran (empty group); the NULL check prevents dereferencing address 0
4. **`borrow_structref` is zero-net-refcount** — increfs on entry, compiler inserts scope-exit decref; safe for temporary access without ownership transfer
5. **Nested allocations** (e.g., `typed.List` inside the structref) are freed by NRT's destructor when `release_meminfo` drops the refcount to 0

### 4.4 Window function additions

`xValue` works like `xFinal` but does NOT call `release_meminfo` — the state persists across the window frame. `xInverse` works like `xStep` but undoes a previous addition (e.g., subtracts a value leaving the window frame). `release_meminfo` happens only in `xFinal` (the true teardown).

### 4.5 No new intrinsics needed

`export_meminfo`, `borrow_structref`, and `release_meminfo` from `numbox/utils/meminfo.py` work unchanged — they operate on raw meminfo pointers regardless of which database engine allocated the slot.

## 7. Out of scope

- **Higher-level UDAF helpers** (e.g., `register_aggregate(db, name, StateType, step_fn, final_fn)`). The pattern from §4 is verbose but matches numbox's "thin wrapper" ethos.
- **Connection/Statement structref wrappers.** Raw `intp` pointers work; numbduck confirms the pattern.
- **UTF-16 variants** (`sqlite3_value_text16*`, `sqlite3_result_text16*`, `sqlite3_result_error16`). Numba uses UTF-8 internally.
- **`sqlite3_value_pointer` / `sqlite3_result_pointer`** — niche inter-UDF pointer-passing interface.
- **Backup API, Serialize/Deserialize, Load Extension, Config** — remain deferred from phase 1.

## 8. Follow-ups

- **Higher-level UDAF registration helper** — convenience that takes a structref type + step/final functions and wires the `sqlite3_create_function_v2` + meminfo bridge boilerplate.
- **`sqlite3_set_auxdata` / `sqlite3_get_auxdata`** — per-argument caching across UDF invocations (useful for compiled regex or parsed format strings). 2 functions.
- **Virtual table interface** — `sqlite3_module` / `sqlite3_create_module`. The heaviest remaining SQLite surface; its own major design.
